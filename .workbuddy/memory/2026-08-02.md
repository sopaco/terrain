# 2026-08-02

## 调研：ccusage 能否以 crate 方式集成进 terrain

**结论：技术上可行，但需权衡"维护新鲜度"。**

### ccusage 项目现状
- 已是 Rust-native（TS 版本已移除），但**只以 npm 分发原生二进制**（各平台 optional dep），**未发布到 crates.io**（`publish = false`）。
- Rust workspace 在 `rust/`：`ccusage`（二进制 `[[bin]]`）+ 多个库 crate：`ccusage-core`、`ccusage-cli`、`ccusage-cli-parser`、`ccusage-config`、`ccusage-terminal`、~17 个 `ccusage-adapter-*`。
- **库 API 已暴露**：`ccusage-core` 有 `pub mod`/`pub use`（`types::*` 含 `UsageSummary`/`TokenCounts`/`ModelBreakdown`/`LoadedEntry`，均 serde）；adapter 提供 `pub fn load_entries -> Vec<LoadedEntry>`、`load_daily_summaries -> Vec<UsageSummary>`；聚合逻辑在 `ccusage_core::summary`（`summarize_by_key`/`summarize_summaries_by_bucket`/`BucketKind`），均为 public。
- 许可证 **MIT**（Copyright 2025 ryoppippi）→ 可 vendoring 源码。
- 工具链要求：edition 2024、MSRV 1.94；依赖 `sqlite`(bundled, 编译 C)、`jiff`(tz db bundled)、`ureq`/`minreq`(联网抓价)、`memchr`、`schemars`、`insta`(dev)。terrain 本机 rustc 1.96.0，满足。

### terrain 当前集成
- `crates/terrain-core/src/usage.rs` 通过 `CcusageLaunch`(Direct 二进制 / bunx / npx) 以**子进程**调用 `daily/monthly/session --offline --json`，再把 JSON 反序列化成自有结构体。
- `bundled_tools.rs` 解析打包/部署的 ccusage 二进制。前端 `UsageBadge.svelte` 用 `UsageProbeResult`。

### crate 集成要点
- 需 git subtree 把 ccusage 的 `rust/` 库 crate 引入 terrain workspace（无法 `cargo add`，不在 crates.io）。
- 调用 `load_daily_summaries` + `ccusage_core::summary` 聚合，替代子进程 JSON 往返。
- 代价：依赖面大（sqlite bundled 编译重、联网抓价、tz db）；~15 crate 需 vendoring；**最大缺点**：pricing/JSONL 格式更新需定期同步上游，而当前 bunx/npx 模型可自动保持最新。

### 倾向
- 子进程模型对"保持价格/格式新鲜度"维护成本更低；crate 集成更快更整洁但把新鲜度责任转移到 terrain 自身。若做，建议 vendoring + 定期 `git subtree pull` 并评估 sqlite/jiff 体积影响。
