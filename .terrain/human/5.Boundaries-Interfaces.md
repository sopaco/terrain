# System Boundary Interfaces

This document catalogs every way external consumers interact with Terrain — CLI commands, Tauri IPC endpoints, ACP tool surfaces, configuration structures, and environment variables. If you are integrating Terrain into CI/CD or wiring an ACP agent, start here.

## Command-Line Interface

The `terrain` binary (`crates/terrain-cli/src/main.rs`) is built with clap and exposes a hierarchical command tree defined in `crates/terrain-cli/src/cli.rs:16-102`.

### Global Options

| Flag | Type | Required | Default | Meaning |
|------|------|----------|---------|---------|
| `--repo-path` | Path | No | cwd Git root or `TERRAIN_REPO_PATH` | Which repository to operate on — all subcommands inherit this |

### Core Commands

#### `terrain scan`

Scans a local Git repository into Markdown knowledge docs (index, Git metadata, optional OpenAPI).

| Argument | Type | Required | Meaning |
|----------|------|----------|---------|
| `repo_path` | Path | No | Repository to scan |
| `--slug` | String | No | Project slug (defaults to directory name) |

```bash
terrain scan /path/to/repo --slug my-project
```

#### `terrain init`

Full project initialization: scan → repomix pack → Litho docs → agent context generation.

```bash
terrain init . --slug terrain
```

#### `terrain refresh`

Quick refresh: re-scan and repack without running Litho. Useful after small code changes.

```bash
terrain refresh --repo-path .
```

#### `terrain search`

Full-text search across the knowledge base.

| Argument | Type | Required | Default | Meaning |
|----------|------|----------|---------|---------|
| `query` | String | Yes | — | Search terms |
| `--project` | String | No | all | Limit to one project slug |
| `--limit` | usize | No | 20 | Max results |

#### `terrain ask query`

DeepWiki knowledge Q&A against project knowledge.

| Flag | Type | Required | Meaning |
|------|------|----------|---------|
| `query` | String | Yes | Natural-language question |
| `--project` | String | No | Project slug |
| `--stream` | bool | No | Emit NDJSON stream events |

### `terrain tools` — ACP Knowledge Layer

These commands output JSON to stdout, designed for ACP agents to consume programmatically (`crates/terrain-cli/src/cli.rs:238-293`).

| Subcommand | Key Args | Purpose |
|------------|----------|---------|
| `list-projects` | — | List indexed project slugs |
| `read-context` | `--project`, `--section` | Read `agent/context.md` by section |
| `grep-pack` | `--project`, `--pattern` | Search repomix source pack |
| `read-pack-file` | `--project`, `--file`, `--start-line`, `--end-line` | Read source slice from pack |
| `search` | `--query`, `--project`, `--limit` | Knowledge doc search |
| `read-doc` | `--project`, `--path` | Read a specific knowledge document |
| `freshness` | `--project` | Get freshness scores |
| `codegraph-drift` | `--project` | Symbol-level drift report |

```bash
terrain tools read-context --project terrain --section "Module Map"
terrain tools grep-pack --project terrain --pattern "ChatEngine" --limit 10
```

### `terrain assets` — Knowledge Generation

| Subcommand | Purpose |
|------------|---------|
| `pack-agent` | Pack source into `agent/repomix.md` |
| `plan-litho` | Show Litho generation plan (skill dir, output paths) |
| `run-litho` | Execute Litho document generation via ACP |
| `agent-context` | Generate `agent/context.md` |
| `list-human` | List generated human docs |

### `terrain env` — Environment Integration

| Subcommand | Purpose |
|------------|---------|
| `status` | Probe Skills, tools, AGENTS.md installation state |
| `plan` | Show diff between current and desired env state |
| `apply` | Deploy skills, tools, and AGENTS.md fragments |

### `terrain sdd run`

Run an SDD workflow phase.

| Flag | Type | Required | Meaning |
|------|------|----------|---------|
| `--project` | String | Yes | Project slug |
| `--phase` | Enum | Yes | `requirements`, `tech-design`, `code-gen`, `code-review` |
| `--session-id` | String | No | Resume existing session |
| `--input` | String | No | Additional context for the phase |

## Tauri IPC Commands

The desktop app exposes Rust functions as Tauri invoke commands (`src-tauri/src/lib.rs:54-80`). The Svelte frontend wraps these in `src/lib/api.ts`.

| Command | Purpose |
|---------|---------|
| `bootstrap_app` | Initial app state (projects, settings, env) |
| `list_projects` | Registered project list |
| `scan_project` | Scan a repository |
| `initialize_project` | Full init workflow |
| `search_knowledge` | Knowledge search |
| `read_document` | Read a knowledge doc |
| `generate_human_docs_cmd` | Trigger Litho generation |
| `run_agent_context_generation_cmd` | Generate agent context |
| `ask_knowledge_cmd` | DeepWiki Ask (with streaming events) |
| `compute_freshness_cmd` | Compute freshness scores |
| `get_model_settings` / `save_model_settings_cmd` | LLM/ACP configuration |

Streaming progress uses Tauri events (not invoke return values) for long-running operations like Litho and SDD.

## Configuration

### ModelSettings

Defined in `crates/terrain-core/src/settings.rs`. Controls LLM provider, model names, and ACP agent configuration.

| Field | Type | Meaning |
|-------|------|---------|
| `provider` | String | `openai`, `ollama`, or `lmstudio` |
| `openai_api_mode` | Enum | `chat_completions` or `responses` — affects API endpoint routing |
| `agent_execution` | Enum | `AcpNative`, `AcpOnly`, `Hybrid` — controls ChatEngine backend selection |
| `acp_binary` | String | Path to ACP agent executable (default: opencode) |
| `acp_args` | Vec | Arguments passed to ACP agent |

### Environment Variables

| Variable | Purpose | Default |
|----------|---------|---------|
| `TERRAIN_REPO_PATH` | Default repository path for CLI | cwd Git root |
| `TERRAIN_LITHO_WORKSPACE` | Litho research artifact directory | `.terrain/.litho-agent/` |
| `TERRAIN_HUMAN_OUTPUT_DIR` | Litho final doc output directory | `.terrain/human/` |
| `TERRAIN_LITHO_TIMEOUT_SECS` | Litho generation wall timeout | 2700 (45 min) |
| `TERRAIN_OPENAI_API_MODE` | Override OpenAI API routing | From settings |

### Knowledge Directory Layout

```
{repo}/.terrain/
├── index.md                 # Project index (from scan)
├── agent/
│   ├── context.md           # Macro architecture context for agents
│   ├── repomix.md           # Source pack (grep-friendly)
│   └── meta.json            # Pack metadata + baseline HEAD
├── human/                   # Litho C4 docs (this directory)
├── knowledge/               # Manual domain glossary
├── .meta/
│   ├── sync.json            # Scan sync state
│   ├── freshness.json       # Asset freshness scores
│   └── human.json           # Litho doc-set baseline
└── .litho-agent/            # Litho research workspace (transient)
```

Project registration pointers live at `~/.terrain/registry.json` (local only, not versioned).

## Integration Recommendations

**CI/CD pipeline** — Add `terrain init --repo-path .` after merge to keep knowledge assets fresh. Use `terrain refresh` for lightweight updates when only source changed.

**ACP agent first steps** — Call `terrain tools read-context --project {slug}` to load macro architecture, then `grep-pack` for specific symbols.

**Freshness gate** — Check `terrain tools freshness --project {slug}` before trusting context. Scores below 50 mean macro context may be stale.

**Conflict resolution** — When sources disagree, trust order is: repomix source > CodeGraph > `context.md` > human docs.
