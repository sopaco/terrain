# System Boundary Interfaces

This document catalogs every way external callers interact with Terrain — CLI commands, ACP JSON tools, desktop IPC, configuration files, and environment variables. Whether you are wiring Terrain into CI/CD, configuring an ACP agent, or scripting asset generation, start here to find the right entry point.

---

## Command-Line Interface (CLI)

The `terrain` binary (`crates/terrain-cli/src/main.rs`) is the primary programmatic interface. All commands accept a global `--repo-path` flag to target a specific repository (default: current Git workspace or `TERRAIN_REPO_PATH`).

### Project lifecycle

| Command | Description | Key source |
|---------|-------------|------------|
| `terrain init [repo]` | Full initialization: scan + Litho + agent context | `commands/init.rs` |
| `terrain scan [repo]` | Scan repo into knowledge index | `ingest/mod.rs:52` |
| `terrain refresh [repo]` | Quick refresh: scan + repack; skips Litho | `workflows/quick_refresh.rs` |
| `terrain list` | List indexed projects | `search.rs` |

### Knowledge access

| Command | Description |
|---------|-------------|
| `terrain search <query> [--project] [--limit]` | Full-text search across knowledge base |
| `terrain read <path>` | Read a document by relative path |
| `terrain ask query <query> [--project] [--stream]` | DeepWiki Q&A with optional NDJSON streaming |

### Asset generation

| Command | Description |
|---------|-------------|
| `terrain assets run-litho <repo> [--force]` | Execute Litho doc generation via ACP |
| `terrain assets agent-context <repo> [--force]` | Generate `agent/context.md` |
| `terrain assets pack-agent <repo>` | Pack repomix source index |
| `terrain assets plan-litho <repo>` | Preview Litho generation plan |

### Environment integration

| Command | Description |
|---------|-------------|
| `terrain env status [repo]` | Show Skills/tools/AGENTS.md status |
| `terrain env plan [--ids] [repo]` | Plan installation steps |
| `terrain env apply [--ids] [repo]` | Install Skills, tools, AGENTS.md patches |

**Example — full project setup:**

```bash
terrain init /path/to/my-repo --slug my-project
terrain env apply --repo-path /path/to/my-repo
```

## ACP Tools API (`terrain tools`)

External coding agents invoke these subcommands for JSON stdout. Each tool maps to an ADK `FunctionTool` in `crates/terrain-agent/src/tools.rs`.

| Tool command | Purpose | Meaning |
|--------------|---------|---------|
| `list-projects` | List registered projects | Discover available knowledge bases |
| `read-context --project <slug> [--section]` | Read `agent/context.md` | Macro architecture layer; use `section` for specific headings |
| `grep-pack --project <slug> --pattern <regex>` | Search repomix pack | Micro layer: find code patterns without loading full files |
| `read-pack-file --project <slug> --file <path>` | Read source slice from pack | Micro layer: precise code reading with line ranges |
| `search --query <text> [--project]` | Full-text knowledge search | Meso layer: find relevant human docs and glossary |
| `read-doc --project <slug> --path <rel>` | Read a specific human/knowledge doc | Meso layer: narrative C4 docs |
| `freshness --project <slug>` | Freshness summary | Check if knowledge assets are stale |
| `codegraph-drift --project <slug>` | CodeGraph drift report | Symbol index freshness |

**Example — agent reads macro context:**

```bash
terrain tools read-context --project terrain --section "Architecture"
```

## Configuration

### Model settings (`~/.terrain/settings.json`)

| Setting | Type | Default | Meaning |
|---------|------|---------|---------|
| `provider` | string | `openai` | Which LLM backend — determines API format and pricing |
| `model` | string | provider-specific | Chat model for native LLM tasks (context, SDD phases 1/2/4) |
| `base_url` | string | provider default | API endpoint override |
| `api_key` | string | — | Authentication for cloud providers |
| `acp.binary` | string | `opencode` | ACP agent executable for Litho and SDD codegen |
| `acp.args` | string[] | — | Extra spawn arguments for ACP |
| `knowledge.incremental_max_changed_files` | usize | 20 | Above this threshold, full regeneration instead of incremental update |

Schema defined in `crates/terrain-core/src/settings.rs`.

## Public Library API

### terrain-core (`crates/terrain-core/src/lib.rs`)

Key exports for embedding Terrain capabilities:

- `KnowledgePaths` — path resolution for `.terrain/` layout
- `ProjectScanner` — multi-collector repository scan
- `KnowledgeSearch` — cross-project document search
- `compute_freshness` — Git drift scoring
- `plan_litho_generation`, `build_litho_generation_prompt` — Litho planning
- `apply_env_integration`, `deploy_agent_toolchain` — agent environment setup

### terrain-agent (`crates/terrain-agent/src/lib.rs`)

Key exports for AI orchestration:

- `Runtime` — shared agent state (paths + model config)
- `run_project_initialization`, `run_litho_generation`, `ask_knowledge`
- `run_sdd_phase`, `run_agent_context_generation`
- `build_agent` — construct ADK agent with Terrain tools

## Integration Recommendations

**CI/CD pipelines**: Run `terrain refresh` on every merge to update repomix and freshness. Run `terrain assets run-litho --force` on release branches for full doc regeneration.

**ACP agents**: Register `terrain tools` commands as available tools. Preload macro context via `read-context` without section; use `grep-pack` → `read-pack-file` for code-level questions.

**Freshness-aware prompts**: Include `freshness --project` output in agent system prompts. Down-weight `context.md` claims when score < 50.

**Env setup order**: `terrain env apply` respects dependency order: terrain-knowledge → repomix → codegraph → rtk (defined in `env-catalog/catalog.json`).
