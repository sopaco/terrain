# 路径布局

**模块路径**：`crates/terrain-core/src/paths.rs`  
**生成日期**：2026-07-22

---

## 这个模块在做什么

路径布局模块定义了 Terrain 所有知识资产的目录结构——`KnowledgePaths` 是整个系统的"地址簿"，所有模块通过它定位 `.terrain/` 下的文件，而不是硬编码路径字符串。这确保了 CLI 与桌面应用、不同操作系统之间的路径一致性。

## 核心功能点

1. **KnowledgePaths 结构**——所有 `.terrain/` 相关路径的根抽象。
2. **目录布局确保**——`ensure_layout` / `ensure_project_layout` 创建标准目录结构。
3. **项目级路径**——`human_dir`、`agent_dir`、`knowledge_dir`、`litho_workspace` 等项目子路径。
4. **元数据路径**——`freshness_meta_path`、`sync_meta_path` 等 `.meta/` 下的文件路径。
5. **跨平台路径**——`path_portable.rs` 处理路径存储格式（正斜杠规范化）。

## 关键组件

| 组件/类型 | 文件路径 | 核心职责 |
|---------|---------|---------|
| `KnowledgePaths` | `paths.rs` | 路径根结构 |
| `ensure_layout` | `paths.rs` | 创建全局布局 |
| `ensure_project_layout` | `paths.rs` | 创建项目布局 |
| `is_knowledge_output_path` | `paths.rs` | 判断是否为知识输出路径 |
| `stored_repo_path` | `path_portable.rs` | 跨平台路径存储 |

## 标准目录布局

```
{repo}/.terrain/
├── index.md                 # 项目索引
├── agent/
│   ├── context.md           # Agent 宏观上下文
│   ├── repomix.md           # 源码包
│   └── meta.json            # 包元数据
├── human/                   # Litho C4 文档
│   ├── 1.概述.md
│   ├── 2.架构.md
│   ├── 3.工作流.md
│   ├── 4.Deep-Exploration/
│   ├── 5.边界接口.md
│   └── 6.数据库概览.md
├── knowledge/               # 领域术语表
├── .meta/
│   ├── sync.json            # 扫描同步状态
│   └── freshness.json       # 新鲜度账本
└── .litho-agent/            # Litho 研究中间产物
```

## 与其他模块的交互

所有 terrain-core 和 terrain-agent 模块都通过 `KnowledgePaths` 访问文件系统，无硬编码路径。

## 实现亮点

单一 `KnowledgePaths` 抽象消除了路径硬编码，是 CLI/桌面路径一致性的基础保障。
