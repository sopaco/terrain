# 系统边界接口文档

本文档描述 Terrain 的外部调用接口，包括 CLI 命令、IPC 命令、配置参数和环境变量。这些接口是用户和外部 Agent 与 Terrain 交互的唯一通道——理解它们就是理解"怎么用这个系统"。

---

## 命令行接口（CLI）

Terrain CLI 是面向脚本和 CI 的"无头展台"，所有子命令通过 `clap` 定义（`crates/terrain-cli/src/cli.rs`），全局 `--repo-path` 可覆盖仓库路径。输出面向脚本：`terrain tools` 子命令输出 JSON，`terrain ask --stream` 输出 NDJSON。

### 项目管理命令

| 命令 | 用途 | 含义解读 |
|------|------|---------|
| `terrain list` | 列出已登记项目 | 查看当前机器上哪些仓库已被 Terrain 管理 |
| `terrain scan <path> [--slug]` | 扫描仓库为 Markdown 知识文档 | 纯离线操作，建立知识资产骨架（index.md + sync.json + pack） |
| `terrain init <path> [--slug]` | 完整初始化（scan + Litho + agent context） | 一键从零到可用，是最常用的启动命令 |
| `terrain refresh <path> [--slug]` | 快速刷新（scan + repack + 可选 context） | 提交后跑一下，几秒钟让知识资产追上代码变更 |

### 知识检索命令

| 命令 | 用途 | 含义解读 |
|------|------|---------|
| `terrain search <query> [--project] [--limit]` | 全文检索知识库 | 在 `.terrain/` 的文档内容中匹配关键词，返回带路径和行号的结果 |
| `terrain read <path>` | 按路径读文档 | 精确读取 `.terrain/` 内的某个文件 |

### 项目状态命令

| 命令 | 用途 | 含义解读 |
|------|------|---------|
| `terrain project overview --project` | 项目总览（新鲜度、文档数） | 一眼看出项目知识资产的健康状态 |
| `terrain project remark/list/remove` | 项目台账维护 | 管理已登记项目的元数据 |
| `terrain project freshness-cached` | 缓存的新鲜度评分 | 不重算，直接返回上次的评分结果 |

### Ask 问答命令

#### `terrain ask query <query>`

**描述**：基于知识库的 DeepWiki 式问答

**参数**：

| 参数 | 类型 | 是否必须 | 默认值 | 含义解读 |
|------|------|---------|-------|---------|
| `query` | String | 是 | - | 自然语言问题，可内嵌 `path:line` 源码引用——这让 Agent 能精确定位到代码行 |
| `--project` | String | 否 | 当前项目 | 限定检索的项目 slug——不传则在全部登记项目中检索 |
| `--stream` | bool | 否 | false | 输出 NDJSON 事件流（chunk/tool_calls/phase/usage/done），便于流水线消费 |

**使用示例**：
```bash
terrain ask query "这个项目的知识保鲜机制是怎么工作的？" --project terrain
terrain ask query "ChatEngine 的双后端路由逻辑" --stream
```

#### 其他 Ask 命令

| 命令 | 用途 |
|------|------|
| `terrain ask sessions-list` | Ask 会话列表 |

### SDD 开发命令

| 命令 | 用途 |
|------|------|
| `terrain sdd status` | SDD 会话状态 |
| `terrain sdd run --phase <phase>` | 执行 SDD 阶段（requirements/tech-design/code-gen/code-review） |

### 工具与环境命令

#### `terrain tools`（面向 ACP/外部 Agent）

`terrain tools` 是面向外部编码 Agent 的 JSON API，所有子命令输出 JSON 到 stdout。

| 子命令 | 用途 | 含义解读 |
|-------|------|---------|
| `list-projects` | 列出登记项目 | Agent 发现当前有哪些项目可操作 |
| `pack-meta` | agent 包的元信息 | 了解包的大小（total_files/total_tokens/baseline） |
| `grep-pack --pattern X [--context N] [--limit N]` | 在 repomix 包中 grep | Agent 的"代码搜索"能力，默认 context=2、limit=20 |
| `read-pack-file --file F [--start-line] [--end-line]` | 读取包内某文件切片 | Agent 的"文件阅读"能力，默认 150 行 |
| `read-context [--section S]` | 读取 agent/context.md | 获取宏观上下文（可只取某章） |
| `search --query X [--limit]` | 知识库搜索 | Agent 的"知识检索"能力 |
| `read-doc --path P` | 按 .terrain 相对路径读文档 | 精确读取某个知识文件 |
| `freshness` | 重算并返回 FreshnessSummary | Agent 判断知识是否最新 |
| `codegraph-drift` | CodeGraph 漂移独立检测 | 交叉验证知识新鲜度 |

**使用示例**：
```bash
terrain tools grep-pack --pattern "ChatEngine" --project terrain
terrain tools read-context --section "核心模块" --project terrain
terrain tools freshness --project terrain
```

#### 其他工具命令

| 命令 | 用途 |
|------|------|
| `terrain usage probe/snapshot` | Token 用量监控 |
| `terrain source read` | 读取实时源码切片 |
| `terrain assets *` | 知识资产生成内部命令 |
| `terrain env status/plan/apply` | 环境集成 |
| `terrain settings get/set/language/check-llm/check-acp` | 设置管理 |

## REST API

本项目不提供 HTTP 服务。`terrain tools` JSON + `terrain ask --stream` NDJSON 是其自动化接口。所有交互通过 CLI 子命令或 Tauri IPC 命令完成。

## 配置结构

### 模型/执行设置

配置文件路径：`~/.terrain/settings.json`（对应 `ModelSettings`，`settings.rs:133-148`）

```json
{
  "provider": "openai|ollama|lmstudio|null",
  "model": "...",
  "api_key": "...",
  "base_url": "...",
  "ollama_host": "...",
  "profiles": { "profile name": { "model": "...", "api_mode": "chat_completions|responses" } },
  "acp": { "binary": null, "args": null, "command": null,
           "agent_execution": "acp|acp_native", "auto_approve": true },
  "knowledge": { "incremental_refresh": true, "incremental_max_changed_files": 60,
                 "incremental_human_docs": false },
  "language": "system|zh-CN|en"
}
```

| 配置项 | 类型 | 默认值 | 含义解读 |
|-------|------|-------|---------|
| `provider` | String | - | 用哪家 LLM 服务——OpenAI 兼容 / Ollama / LM Studio，决定 API 格式与定价 |
| `acp.agent_execution` | enum | `acp` | `acp` = 纯 ACP worker（默认）；`acp_native` = 混合：Native LLM 处理轻量/文档阶段，ACP 处理重工具阶段 |
| `acp.binary/args/command` | String? | opencode / acp | ACP 子进程的二进制、参数或完整命令；也可以不配置走默认 |
| `knowledge.incremental_refresh` | bool | true | 默认按 git diff 增量更新知识——小提交只花极短 diff 回合 |
| `knowledge.incremental_max_changed_files` | u32 | 60 | diff 变更文件数上限，超过则退回全量重建（防"增量吃到撑"） |
| `knowledge.incremental_human_docs` | bool | false | 快速刷新时是否顺带增量更新 human/ 文档（最慢的一步，默认不开） |
| `language` | enum | system | CLI 输出/知识资产/Agent 回答的语言；zh-CN 优先 |

### 环境变量覆盖

环境变量优先级高于配置文件，适合 CI 或临时调试：

| 环境变量 | 覆盖的配置项 | 含义解读 |
|---------|------------|---------|
| `TERRAIN_LLM_PROVIDER` | `provider` | 临时切换 LLM 提供商 |
| `TERRAIN_MODEL` | `model` | 临时切换模型 |
| `OPENAI_BASE_URL` | `base_url` | 临时切换 API 端点 |
| `OLLAMA_HOST` | `ollama_host` | 临时切换 Ollama 地址 |
| `TERRAIN_OPENAI_API_MODE` | `api_mode` | 切换 chat_completions / responses 模式 |
| `OPENAI_API_KEY` / `TERRAIN_API_KEY` | `api_key` | 设置 API 密钥 |
| `TERRAIN_ACP_COMMAND` | `acp.command` | 临时切换 ACP 命令 |
| `TERRAIN_ACP_BINARY` | `acp.binary` | 临时切换 ACP 二进制 |
| `TERRAIN_REPO_PATH` | `--repo-path` | 临时覆盖仓库路径 |
| `TERRAIN_REGISTRY_FILE` | registry 路径 | 临时切换 registry 文件 |
| `TERRAIN_LITHO_TIMEOUT_SECS` | Litho 墙钟超时 | 调整 Litho 的超时时间 |
| `TERRAIN_LLM_COOLDOWN_MS` | LLM 冷却时间 | 调整 ThrottledLlm 的冷却间隔 |
| `TERRAIN_LITHO_SKILL` | Litho Skill 路径 | 注入 Litho Skill 到 ACP 环境 |
| `TERRAIN_HUMAN_OUTPUT_DIR` | human/ 输出目录 | 注入输出目录到 ACP 环境 |
| `TERRAIN_LITHO_WORKSPACE` | Litho 工作区 | 注入工作区到 ACP 环境 |
| `TERRAIN_SDD_*` | SDD 相关注入 | SDD 阶段的环境变量注入 |

## IPC 命令面（桌面端）

Tauri 桌面端提供约 60 个 IPC 命令（`src-tauri/src/lib.rs:56-112`），覆盖以下分组：

| 命令分组 | 示例命令 | 说明 |
|---------|---------|------|
| bootstrap | 首启探测 + 环境部署 | 自动化初始化 |
| project | list/scan/init/remove/overview | 项目管理 |
| knowledge | search/read | 知识检索 |
| freshness | compute/cached | 保鲜评分 |
| workflows | quick_refresh | 快速刷新 |
| litho | plan/assets/list_human_docs/run | 文档生成 |
| agent_context | generate | Agent 上下文生成 |
| sdd | status/create/set_active/delete/save/run | SDD 工作流 |
| chat | sessions/load/save/ask | Ask 问答 |
| env | status/plan/apply | 环境集成 |
| usage | probe/snapshot | Token 用量 |
| settings | get/set | 配置管理 |
| util | open_path/copy_clipboard/save_png | 工具函数 |

流式输出通过 Tauri Channel 推送 AskStreamEvent，进度事件通过 `listen` 机制推送。

## 集成建议

### CI 合入时刷新

```bash
terrain refresh .
terrain project freshness-cached --project <slug>
```

低成本刷新 + 新鲜度检查，适合在 CI 任务日志中输出。

### 外部 Agent 接入

让 Agent 把 `terrain tools` 作为唯一源码入口：

```bash
# Agent 的知识消费 API
terrain tools grep-pack --pattern "关键词" --project <slug>
terrain tools read-pack-file --file "src/main.rs" --project <slug>
terrain tools read-context --project <slug>
terrain tools search --query "问题" --project <slug>
```

与 Ask-ACP 的 `TERRAIN_KNOWLEDGE_ROOT` / `TERRAIN_PROJECT_SLUG` 约定保持一致。

### CLI vs GUI 选择

- **桌面端**：适合交互探索，可视化浏览 C4 文档和新鲜度评分
- **CLI**：适合 CI/CD 和自动化，`terrain init/refresh/tools` 均可脚本化，无需桌面环境
