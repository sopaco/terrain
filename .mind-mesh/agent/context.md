## 项目概览

MindMesh 是一个工程环境管理平台，用于为 AI 编码助手（如 OpenCode）提供结构化的项目知识库。它输入 Git 仓库，通过核心库（core）进行项目分析，利用 Litho 生成人类可读文档（Ask 模式），并构建 Agent 专用的紧凑上下文（context.md）。系统以 CLI 和 Tauri 桌面应用为入口，输出标准化的知识资产包。

## 架构设计

### 容器与分层

| 容器 | 职责 | 备注 |
| :--- | :--- | :--- |
| 桌面应用 (Tauri) | 前端交互，文件管理，任务调度 | `src/`, `src-tauri/` |
| CLI 工具 | 命令行入口，Git 扫描触发点 | `crates/mind-mesh-cli/` |
| 核心引擎 (Core) | 项目解析，Litho 编排，Ask 推理 | `crates/mind-mesh-core/` |
| AI 代理层 (Agent) | 上下文生成，ACP 协议实现 | `crates/mind-mesh-agent/` |

### 模块与依赖关系

- `mind-mesh-core` 是所有核心逻辑的基石，被 CLI、Agent 和桌面应用层引用。

- `litho-documents-skill` 和 `repomix-context-skill` 是核心引擎调用的可插拔技能。

- `agent` 容器通过 `env-catalog` 动态加载技能包。

## 核心流程

1. **初始化 (Init)**: CLI 或 UI 扫描仓库，检测 `.mind-mesh/meta` 配置文件，触发 Git 扫描与 Repomix 打包，生成项目元数据（project_meta）。

2. **Litho 生成 (Ask)**: 用户触发问句，引擎从技能包加载 Litho 技能，读取项目上下文与 repomix，通过 Agent 执行研究、编排、输出，生成人类文档。

3. **Agent 上下文 (Context)**: 用户请求“架构上下文”，引擎调用 `agent/context_generator`，合并 meta、repomix 与 Litho 生成的内容，构建 `agent/context.md` 写入磁盘。

4. **ACP 交互**: CLI/Agent 通过 ACP 协议接收外部请求（如“解析代码”），内部路由至对应 Tauri 命令或 Agent 逻辑，返回结构化响应。

## 技术选型

- **语言**: Rust (核心逻辑)

, TypeScript/Svelte (前端), Node.js (部分 CLI/工具)。- **前端框架**: Svelte + Tauri (桌面应用，跨平台)。- **AI 代理**: LiteLLM 封装的 LLM 接口，通过 ACP 协议交互。- **构建**: Tauri CLI, Vite, cargo-binstall。- **协议**: ACP (Agent Communication Protocol) 用于 AI 交互。

## 系统边界

- **Git 仓库**: 输入边界，MindMesh 可扫描任意结构化 Git 仓库。- **LLM API**: 外部依赖边界，MindMesh 通过 HTTP/gRPC 调用外部大模型（非本地模型）。- **Local Disk**: 输出边界，所有生成的知识资产（`.mind-mesh/` 目录）存储于本地文件系统。- **ACP Client**: 外部边界，MindMesh 作为 ACP 客户端被其他 Agent (如 OpenCode) 调用，边界通过 CLI 暴露。- **Human Docs**: 逻辑边界，Litho 生成的 Markdown 仅用于人类阅读，不被 Agents 直接消耗（除非 Ask 模式引用）。
